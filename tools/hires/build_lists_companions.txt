# Companions of check_build_lists.py: pairs of files that must be listed together. Wherever a build
# description lists the first file, it must list the second one too:
#   - every variable and every rule (prerequisites and recipe) of each Makefile.am, Makefile.common
#     and Makefile.mingw, under the same conditionals or fewer (so not only inside "if BUILD_EXULT");
#   - every *.vcxproj and *.vcxproj.filters under msvcstuff (Exult, Exult Studio, the tools);
#   - every target of ios/Exult.xcodeproj, and its file references.
# One entry per line: <first> <second>, repository-relative, then an optional "# reason". A source and
# its object are the same file (imagewin/ibuf8.cc matches imagewin/ibuf8.o). An entry stays inactive
# until its second file exists or is listed somewhere; with --strict, an entry whose first file is
# listed nowhere fails.

# DESIGN.md section 6.1: the hooks in ibuf8.cc call the scaled primitives, so ibuf8_scaled.cc (WP-04)
# is compiled everywhere ibuf8.cc is.
imagewin/ibuf8.cc    imagewin/ibuf8_scaled.cc
imagewin/imagewin.cc imagewin/world_present.cc

# WP-08: shapeid.cc calls Hires::invalidate() from hires_glue.cc. hires_glue.cc in turn needs
# shapes/hires_store.cc, hires_bundle.cc, hires_png.cc and hires_rules.cc; those come with the
# shapes library (shapes/Makefile.am, SHAPES_OBJS in Makefile.common), so they are not pairs here.
shapeid.cc           hires_glue.cc

# WP-10: keys.cc binds the dev key actions of hires_dev.cc (exult.cc calls its .reload poll too,
# but exult.cc also names the program in rules that list no sources, so keys.cc stands for both).
keys.cc              hires_dev.cc
