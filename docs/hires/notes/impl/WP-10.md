### Behaviour

* **Gating.** The keys are cheat keys, so `KeyBinder::DoAction` drops them while cheats are off. They also need
  `config/video/hires/dev=yes`. Without it, a key logs `[hires] the hi-res dev keys need config/video/hires/dev=yes`,
  shows the toast "Hi-res dev mode is off" and does nothing else.
* **HIRES_TOGGLE.** `set_enabled(!enabled)`, so the generation changes. Then `set_all_dirty()` and the toast
  "Hi-res overrides on|off (xS)", also printed to stdout.
* **HIRES_RELOAD.** `Hires::reload(S)` at the window's world scale: it rescans and revalidates every root, re-reads
  the config and logs the store report as before. Then `set_all_dirty()` and the toast
  "Hi-res x6: 3880 loaded, 5 rejected (see log)". The suffix appears only when there are rejects or warnings. Other
  toasts: "load failed (see log)", "no override roots", "reloaded (world scale 1)".
* **HIRES_INSPECT.** The mouse is already in game coordinates (`Mouse::get_mousex`), so the tile is
  `scroll + mouse / 8`, as in `Cheat::cursor_teleport`. `explain_at` reports: tile, map, chunk, cell, terrain number,
  T1 key, own shape:frame and kind, effective source (cell and shape:frame&31, from `Chunk_terrain::get_flat_source`,
  the engine's own fill), the terrain override and the tile override. The result is `TILE <where>`, `NN (<reason>)`
  or `none (no flat source: <kind>)`. Output:
  * 4-5 lines on stdout (`[hires] inspect: ...`);
  * the same text, with the absolute file path, on the clipboard (`SDL_SetClipboardText`);
  * a short `center_text` toast such as `810,1340 0027:25 TILE`, cut to 44 characters because the 320 px game area
    in font 0 holds about that many.
* **`.reload` poll.** Only in dev mode, from the main loop, at most every 500 ms. It compares the mtime (and
  existence) of each trigger with the previous poll. Any change, including creation or removal, calls
  `dev_reload(S)`, `set_all_dirty()` and a toast. The first poll only records a baseline. A trigger path seen for
  the first time (a new root or scale) also counts as baseline only. Dev mode off resets the watch.

## 3. Deviations from the spec (the code is the truth)

1. **Trigger files.** §3.8 names `<root>/x<S>/.reload`. Packs have only `x<art_scale>` folders (the store reduces),
   and the tools touch `x6/.reload`. The poll therefore watches `<root>/x<art_scale>/.reload` for every root, and
   also `<root>/x<S>/.reload` when the render scale S > 1 differs from the art scale.
2. **Terrain overrides are reported, not painted.** WP-17 has not wired `Hires::terrain`, so the inspector's
   `result` follows today's precedence (tile → NN). The terrain answer is reported separately: `terrain_override`
   in the JSON, and "[not painted before WP-17]" in the text when a terrain file exists.
3. **`explain_at` creates no chunk.** It uses the chunk's terrain when the chunk is in memory. Otherwise it uses the
   map's terrain number through `Game_map::get_terrain` (a terrain read, as a paint would do). It loads the terrain's
   frames (`get_shape`), which paint does anyway. It never changes game state (I4, I8).
4. **`inspect=` output.** The spec says "JSON of explain_at". The harness writes `inspect.json` with
   `{"inspect": [ … ]}`, one object per tile and scale, and adds `inspect_<tx>_<ty>_s<S>` = result to the digest.
   The key may repeat. It runs after every other step, because loading frames changes the heap order and therefore
   the dependency paint order (WP-00 finding 2).
5. **New render-test keys `dev=1` and `keys=1`** (not in §4.2). They are the "small test hook" the task asked for,
   because the keyboard cannot be automated here (WSLg has no xdotool). `dev=1` needs a pack with
   `x<S>/flats.next` (or `x<art>/flats.next`) holding identity flats, and it renames directories in the first root.
   Use scratch packs only.
6. **Glue API change.** `Hires::explain_flat` and `explain_terrain` now return `Hires::Explanation` instead of a
   string (WP-08 had made them for WP-10; nothing else used them). Paths in `where` are root-relative so the golden
   is stable.
7. **Dev-mode-off toast.** The text is "Hi-res dev mode is off", plus a log line naming the config key, because the
   full key does not fit the 320 px toast.
8. **The poll is in the main loop only** (`Handle_events`). While a modal gump loop runs (for example a Scroll_gump),
   no poll happens. The reload follows on the first main-loop frame after it.
9. **`Inspection::toast()`** shows tile, source shape:frame and result. Long NN reasons are cut to 44 characters. The
   full text is on stdout and the clipboard.
