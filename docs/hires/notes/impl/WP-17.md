## 1. What was done

| Area | Change |
|---|---|

| Store | `Store::has_terrain(key)` (indexed and not latched as rejected); `Store_set::terrain_count(scale)` and `has_terrain(key, scale)` (0/false when disabled, at S < 2 or after a failed load). | Glue | `Hires::terrain_count(scale)`, `Hires::has_terrain(key, scale)` |
| `Chunk_terrain` | `get_t1_key()`: T1 over the terrain's own non-RLE flats (as `dump_art.cc` and `hires_dev.cc` compute it), cached in `t1_key`/`t1_gen`/`t1_valid`; invalid after `set_flat`, `abort_edits` and any `Hires::generation()` change (shapes reloaded, toggle, reload). `paint_hires_terrain(dst)`: at S > 1 with overrides, when the store has terrain overrides at all and one for this key, paints the terrain's 1x layer (`paint_flats(1x, false)`, fill included) as the parent for P4 and the reduction, decodes into a 128S² buffer and `put_phys`es it; any failure (`bad_alloc` included) falls back per tile (I11). `paint_flats` tries it first: **terrain → tile → NN** |
| Inspector | `hires_dev.cc`: the result is `TERRAIN <where>` when the terrain override paints the cell (indexed or loaded, not P4-rejected on its last decode), RLE cells without a flat source included |
| `--render-test` | the cell grid counts a cell under a painting terrain override as covered (`has_terrain`), cells without a flat source included, and records `(N by terrain)`; new key `marked=any|terrain` (with `expect=marker`): `terrain` predicts the marker only on terrain-covered cells (the tile overrides are identity) and fails when no terrain override paints a cell of the view |

## 2. Deviations and open points

1. **Decode on every cache render.** `Store::terrain` reads and checks the PNG each time a flats cache of that
   terrain is painted (≈1.2 ms for 768², as §3.5 planned). Caches are kept LRU, so this happens when chunks come
   into view. If WP-15-style walk measurements show hitches with many terrain overrides, add a small decoded-pixel
   cache in the store (keyed by T1 and the layer's CRC, because P4 depends on the layer).
2. **`terrain-reduce-britain` uses `coverage=partial`.** A terrain-only pack covers only the chunks whose key was
   written; if every chunk of that view happens to be covered, `partial` fails and the case should become `full`.
   Check on the first run.
3. **T1 computation loads all 256 frames of the terrain** before the per-tile loop when the pack has terrain
   overrides at that scale (the per-tile loop loads them too, in a different order). S = 1 and packs without
   terrains are unaffected (`terrain_count` gate).
4. The terrain editor path (`render_all`) stays NN (§1.4 item 4).
