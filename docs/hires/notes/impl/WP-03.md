## 2. Item details

### 2.1 P3 (01)

`render_flats()` allocates `rendered_flats` with `new[]` and paints only the cells that get a flat. A cell whose
own frame does not exist (BG's flat 48/8: shape 48 has 5 frames, checked in `shapes.vga`) or an RLE cell in a
chunk without any flat is never written, so it shows heap garbage, and a re-render after `commit_edits()` keeps
the old pixels. The fix is `rendered_flats->fill8(0)` before the paint loop (3 lines). In item 02 the fill moves
into `paint_flats()` (§3.4: `dst.fill8(0); // P3`). As WP-00 found, P3 does not change BG's buildmap (§5).

### 2.2 `find_flat_source()` and `paint_flats()` (02)

`objs/flat_source.h` (header-only; it includes only `exult_constants.h`):

```cpp
enum class Tile_kind : uint8_t { None, Flat, Flat_void /*12/0*/, Rle };
inline bool Is_flat(Tile_kind kind);   // Flat or Flat_void
template <class Is_void_fn, class Kind_fn>
int find_flat_source(int tx, int ty, Is_void_fn is_void, Kind_fn kind_of);   // tile 0..255 or -1
```

**Deviation from §3.4: two callables, not one.** In the engine, `kind_of(t)` must call `get_shape()`, and
`get_shape()` allocates on first use (the `Shape_manager` cache node and the frame). The heap address order
decides ambiguous overlaps in the buildmap (WP-00 finding 2), so the refactor keeps the frame loads of the old
loop exactly. The old loop skipped the void tile 12/0 in the 3x3 pass **before** loading its frame, by looking
at the ID (`get_flat`). A single `kind_of` would have to load the frame to report `Flat_void`, which is one load
the old code never made. So `is_void(t)` checks the ID only, and `kind_of(t)` is called exactly where the old
loop called `get_shape()`: the tile itself, then the in-bounds non-void neighbours, then the whole chunk,
stopping at the first flat. The test pins that order (below). `Flat_void` remains in the enum, as §3.4 and
the `--dump-art` kind byte (§4.2) need it.

`Chunk_terrain::paint_flats(Image_buffer8& dst, bool overrides)` (public) replaces the private `paint_tile()` and
the loop in `render_flats()`. It does `dst.fill8(0)`, then `copy8` of `shapes[src].get_shape()` for every
cell with `src >= 0`. These are the same calls as before; the second `get_shape()` is a cache hit and
allocates nothing. `render_flats()` calls `paint_flats(*rendered_flats, true)`. The `overrides` flag is the
§3.4 signature: the minimap passes `false`. Nothing reads it before WP-09 (`ignore_unused_variable_warning`).
I kept it so that the call sites of these existing functions stay final, which the rebase rule asks for.

`tests/unit/test_flat_source.cc` (6 cases):
* targeted cases: own flat and own void tile paint themselves, and a tile without a frame gets nothing;
  the first flat neighbour wins, row by row; edges; **row 0 never fills a neighbour** (P1 quirk); **the
  void tile is skipped among the neighbours but not by the chunk search** (P2 quirk), with an exact
  `kind_of` call list; near misses 12/1 and 13/0; a void tile without a flat frame; a chunk without flats;
* a fuzz test against `legacy_source()`, a statement-by-statement transcription of the old `paint_tile`
  (upstream `chunkter.cc:86-133`) whose `get_shape()` logs its calls. On 2,000 random chunks × 256 cells the
  source **and the call list** must be equal. Coverage counters prove that every path ran: itself 100,908,
  neighbour 161,026, chunk search 175,304 (void tile returned 23,772), nothing 74,762, row-0 neighbour passed
  over 11,798.
* Mutation check (`tmp/wp03/mutants/run_flat.sh`; mutants of `flat_source.h` compiled out of tree): P1 fixed,
  P2 fixed, void skip removed, `kind_of` before `is_void`, column-major neighbourhood, `Flat_void` not
  counted as flat, self not re-queried, `None` treated as RLE. All 8 are detected. `kind_first` and `skip_self`
  change only the load order, and only the call-list check catches them.

### 2.3 `write_minimap` (03)

`Game_map::write_minimap()` paints each terrain with `ter->paint_flats(flats, false)` into one local
`Image_buffer8 flats(c_chunksize, c_chunksize)` and averages that. It used `get_rendered_flats()`, which built
the cache of all 3,072 terrains in turn and evicted the view's chunks. The values are the same for every
terrain whose cache was current. A terrain whose cache was out of date (terrain edits not committed yet,
shapes reloaded from Exult Studio) now counts with its current flats. Callers: the key action
(`keyactions.cc:819`) and Exult Studio through the server (`server.cc:587`). This path was not run here
(manual: needs Exult Studio or the key binding).

### 2.4 `Figure_queue_size` (04)

The formula from the original author's comment: `max(100, (cw + 3) * (ch + 3))`, where `cw` and `ch` are the
game area's chunks, rounded up, from `Game_window::get_width()/get_height()`. Up to about 7×7 chunks plus margin
it stays 100; 1720x600 gives 136; `--buildmap`'s 2048x2048 gives 361. **Heap-order risk checked:** the larger
queue changes the allocation pattern during the buildmap (fewer frees and reallocations of 16 KB flats
buffers). WP-00 finding 2 says that can flip ambiguous overlaps, but the buildmap stayed byte-identical at all
three levels in two runs (§5).

### 2.5 Main-buffer wiring (05; D-24, CC-1, MS-4, PS-6)

* `imagewin.h`: `Image_buffer* main_ibuf` (declared after `ibuf`, initialised from the constructor's `ib`);
  clang-format reflowed the initializer list (4 lines).
* `imagewin.cc`: a file-local RAII class `Ibuf_scope` (non-copyable). `create_surface()` starts with
  `const Ibuf_scope main_buffer(ibuf, main_ibuf);`, **before** its own `free_surface()`. Every `ibuf->`
  inside, including `get_full_width()`, `get_start_x()` and `ibuf->depth` in `create_scale_surfaces`/
  `try_scaler`, then means the main buffer, and `ibuf` is restored on return and when the "Failed to creat
  Display Sorfaces" exception is thrown. `free_surface()` nulls `main_ibuf->bits`, and `~Image_window` deletes
  `main_ibuf`.
* Not done here (S>1 tail, WP-05): `pixel_scale`/tracker wiring and the I12 assert.
* `Image_window8::ib8` is untouched. `create_surface` never changes the current target, so `ib8` and `ibuf`
  stay consistent.

**Resize-while-pushed check** (§6.7: "manual here"). This is a throwaway probe, not committed, because WP-07
automates it as `pushed_resize=1`: `tmp/wp03/pushed_resize/{probe.cc,stubs.cc,build.sh}`. It drives a real
`Image_window8` with the dummy video driver, linked against a lane's `libimagewin.a`, `libconf.a` and

3. pop, check the main buffer (size, pitch, offsets, `bits` = first game pixel of the new surface) and fill
   it;
4. resize back while pushed and check again;
5. destroy the window while a stack buffer is pushed.

### 2.6 `Import_png8` leak (06; CC-8, D-11)

The `setjmp` handler (`pngio.cc:80-84`) now frees and nulls `palette` (allocated at 107) and `pixels`
(137-138). They are reference parameters, so their values survive the `longjmp`; the function nulls both on
entry, so whatever is non-null in the handler belongs to this call. **Extension:** `Import_png32` has the same
handler and leaks its `pixels` the same way, so it gets the same 2-line fix in the same commit. It has no caller
in the tree today.

`tests/unit/test_pngio.cc` (3 cases): the round trip `Export_png8` → `Import_png8`; then four broken files for
each importer: ends before IDAT (fails before any allocation), ends in the IDAT data, ends before IEND, and an
IDAT with a bad CRC. Each must return 0 with `pixels` (and `palette`) null. The files go to
`hires_test::scratch_path()`, new in `test_support.h`/`main.cc`: `$HIRES_TEST_TMP`, else the current
directory, so the build tree under `make check`. They are removed afterwards. Negative control: the same test
objects linked against `build-upstream`'s unfixed `libshapes.a` fail 9 checks (3 post-allocation cases × 2 in
`Import_png8`, × 1 in `Import_png32`), and the pre-allocation case passes in both. Under ASan with
`detect_leaks=1` the fixed code is clean.
