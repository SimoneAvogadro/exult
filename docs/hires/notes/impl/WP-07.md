### 1.1 How a run works

Like `BuildGameMap`: gamma 1, `Game_window`, `Audio::Init`, `create_game`, `init_files(false)`, then
`srand(seed)`, map 0, palette 0; `vsync` is set to 0 in memory (the bench times the present, not the
display). The scale-1 reference is painted once (again after a terrain edit). Two targets for the S render:

* **pushed** (default): the window is 1x (`render_scale` override `off`), and each S render goes into
  `Image_buffer8(w, h, S)` through `push_render_target`, the reference into `Image_buffer8(w, h)`;
* **window** (when `present`, `game`, `resize` or `pushed_resize` is given): the window's own buffer at
  world scale S (override `force:S`, `Game_window::resized` for each further S), the reference is a 1x view
  with the same offsets. Every switch is checked against I12 (draw surface = main w,h × S + guard band,
  `pixel_scale == world_scale`, tracker iff S>1, the expected S).

Per S: full paint (cleared first) → digest, O7 (`mini_screenshot` digest equal to the
reference's; not the light-source count, see §2.5), O2 (`phys(S) == NN(ref)` over the whole storage extent, including the offset band), O6
(`repaint=N`: random sub-rects of the game area are first spoilt with index 1 and then repainted as a
dirty repaint, in the S target **and** the reference; after each one the S target must still be NN of the
reference; the count of repaints that changed the reference is recorded, 0 in every BG region), bench.
Then present, resize steps, the terrain edit, the pushed resize.

* **Present** (one S, window `w·S × h·S` or `window=`, an integer multiple of `w x h`): per format, a
  read-back after the render (first upload of the new textures) and after three tracked `fill8` rects
  that the reference mirrors (random, also over the offset band, so `tracked_to_phys` with `offset_x = 17`
  is exercised by partial uploads); each against `LUT(NN(ref))`, exact at 1:1, else within 1 of a C port of
  SDL's `scale_mat` (software renderer LINEAR, 7-bit fractions; measured max error 0). `format=both`
  rebuilds the surfaces with the other `present_format` in the same process and requires the two
  read-backs to agree within 1 (measured 0). Then `screen_to_game` on a 16x16 grid at S equals the grid
  after switching the same window to S=1.
* **Terrain edit** (`edit=1`, W6-3): from the centre of the view outwards, a cell gets another flat of
  its terrain (`set_flat` + `commit_edits`) after a full paint at S, so `commit_edits` re-renders the cache
  at S; the S render and a new reference must be NN-equal; a cell whose change is hidden under objects is
  undone and the next one tried.
* **Pushed resize** (CC-1, MS-1): a 64x32 layer with a pattern is pushed; `Game_window::resized` with the
  same parameters, then two `toggle_fullscreen()` (under the dummy driver: 1024x768 fullscreen, then a
  768x768 window, since upstream's toggle passes the display height twice); the layer's bits pointer and
  pixels must be unchanged and the layer still the target; after the pop the window's buffer satisfies I12;
  a final `resized` restores the window, I12 at the original S, and an O2 render.

## 2. Deviations from the spec (the code is the truth)

1. **Images.** §4.2 lists `ref_1x.png` and `hi_S.png` as outputs of every run. They are written in
   `mode=plain`, with the new key `images=1`, and on a failure (then with `diff_<tag>.png`, the mismatching
   game px in magenta, and for the present `present_*.png` plus the expected image). The oracles compare in
   memory; writing 3840x2400 PNGs for every region and scale would cost seconds per run and disk. The
   digests of all images are always in `digest.json`.
2. **New keys:** `format=both` (ARGB and INDEX8 in one process, for "ARGB == INDEX8 ± 1"), `edit=1` (the
   terrain-edit step of §6.4/§12.3 W6-3), `images=1`. `resize` steps are `off`, `art`, `auto`, `forceN`
   (§4.2's own example `force6:off:…`; `force:N` cannot be written there because ':' separates the steps).
3. **Not available yet (rejected with exit code 2):** `overrides=yes`, `expect=identity|marker:<idx>`,
   `inspect=`. They need the hi-res store, which is on `hires-store` and merges in WP-09/WP-10. `passes=flats`
   (the marker-prediction mode) is implemented. `mode=nn` implies `expect=nn`.
4. **`present=1` takes exactly one scale**, and the window must be an integer multiple of the full area
   (so `screen_to_game` and the letterbox are exact); the read-back oracle covers ratios ≥ 0.5 (1:1 and
   LINEAR; the halving chain stays covered by `hires_present`).
5. **`render_test_paint` instead of `paint_map_at_tile`.** O6 needs a dirty repaint's chunk range, which
   `paint_map_at_tile` cannot give. **O7 compares only the mini screenshot** (review fix): `paint_map`
   counts light sources only around a main actor, and `--render-test` (like `--buildmap`) has neither a
   main actor nor the ireg objects that carry the lights, so the count was always 0 and proved nothing;
   `render_test_paint` returns nothing.
   Rather than change `paint_map_at_tile`, a new `Game_window` member is declared in `gamewin.h` and defined in
   `render_test.cc`; `paint_map_at_tile` and `Game_window::paint` are unchanged.
6. **O6 is stronger than "unchanged":** the sub-rect is spoilt before the repaint, so a missing write is
   caught as well as a wrong one (a skip mutation of the S>1 chunk clip test passed the plain "unchanged"
   check but fails this one, §4.3). The repaint is applied to the reference too, so a sub-rect artefact of
   upstream's dirty repaint would not count against S (none occurs: `repaint_ref_changed` is 0 everywhere).
7. **Present read-back also covers tracked partial uploads** (three fills per format), not only the upload
   after the render. `upload_world()` and `read_back_world()` are new public `Image_window` members (test
   hooks); `show_world_scaled` calls `upload_world()` for the upload it did inline.
8. **Perf.** `perf.sh` is a new script (§6.1's file list has only `perf_baseline.json`). It measures the
   320x200 view (gate p95 ≤ 2.0 ms) and also the user's 860x300 view (baseline only). The 20 % rule gets an
   absolute slack of 0.05 ms (a p95 of 0.2 ms moves by more than 20 % with timer noise), and a failing gate
   is measured once more before it counts. Baseline keys are `"<host>/<case>/paint_p95_ms"`. The upload and
   present numbers come from the software renderer under the dummy driver and are reported only. The
   "cold `render_flats` with per-tile art ≤ 1 ms" row needs the store (WP-09).
9. **`buildmap_golden.sh` is skipped in an ASan build** (77): the ASan allocator changes the heap order, so
   its lists are never compared (§6.4); `smoke.sh` keeps a buildmap run in that lane.
10. **Goldens recorded in the new harness are identical to the old ones.** §6.4 says to regenerate the
    `build-upstream` lists when the harness changes; they were regenerated (`regen_goldens.sh`, two runs per
    level) and came out byte-identical to `tmp/goldens-ref/buildmap{0,1,2}-upstream-ref-run1.sha256`
    (list SHA-256 `b0f5f4a8…`, `c81e117d…`, `d2eeca25…`), although the config now carries `hires_path` and
    `render_scale=art`.
11. **`test_passes` is a public member** of `Game_render` (no setter); the `passes=flats` hook is a
    three-line `if` (house style needs the braces).
12. The design's §6.1 file list names `resize_cycle.sh` for the S cycle only; it also runs the pushed
    resize and the pushed-target edit (one script per window-state topic).

* `overrides=yes`, `expect=identity|marker:<idx>` and `inspect=` are rejected (exit 2) until the hi-res
  store lands (WP-09/WP-10); O4a/O4b and the cold `render_flats` perf row come with it.
* O7 is the mini screenshot only; the light-source count is not observable headless (no main actor).
* The present read-back covers 1:1 and LINEAR ratios ≥ 0.5 with exactly one scale and an integer-multiple
  window; the halving chain stays covered by `hires_present`. The read-back runs on the software renderer
  under the dummy driver only.
* `perf_baseline.json` has only this host's (`SevenJars`) lines; WP-15 adds the Windows host.
* `buildmap_golden.sh` and `perf.sh` are skipped in the ASan lane.
