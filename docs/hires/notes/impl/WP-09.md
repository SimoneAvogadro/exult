## 2. The render-test oracles

* **Coverage** (every S render with overrides on, S > 1): per tile of the full area, `get_flat_source` (the
  engine's own fill) and `Hires::flat` of that source give "flat cells" and "overridden cells"; both and the
  store's report counts go into `digest.json` (`s6_cells`, `s6_store`). `expect=identity|marker` fails unless every
  flat cell of the view is overridden: an identity render alone cannot tell overrides from NN, so without this a
  pack that failed to load would pass.
* **O4a** (`expect=identity`): the same NN check as O2 (`phys(S) == NN(ref)` over the storage extent), plus O7
  (mini screenshot) and O6 (repaints) as before.
* **O4b** (`expect=marker:<idx>`): with `passes=flats` the S render must equal the prediction exactly: the reference
  pixel everywhere, except the top-left sub-pixel of every logical pixel whose cell has an override, which is the
  marker (diff image of mismatching game px on a failure). With `passes=all` the S render must differ from NN of
  the reference (count recorded). Repaints must leave the marker render unchanged byte for byte; O7 is recorded
  only (the mini screenshot samples the top-left sub-pixels, i.e. the markers); `present` and `edit` are refused
  with a marker (their oracles are NN).
* **Toggle** (`toggle=1`, I8): after each S render, `Hires::set_enabled(false)` and a full repaint must give NN of
  the reference (the flats caches notice only through `Hires::generation()`), then `set_enabled(true)` must give
  the first render back. Works for pushed targets and the window's buffer (offsets).
* **Bench** with `overrides=yes`: N extra cold paints (toggle off/on before each, so every flats cache of the view
  renders again with its overrides while the store stays loaded); `bench_<tag>_render_flats_p95_ms` = (cold p95 −
  warm median) / caches of the view.

## 3. `mkpack_identity.py`

`mkpack_identity.py STATIC OUT [--kind identity|marker] [--marker M] [--scales 2,3,6] [--bundle] [--force]`.
It reads `shapes.vga` (non-RLE entries, frames 0-31, the engine's RLE test) and palette 0 of `palettes.flx`
(768 or 1536 bytes, `min(255, v·255/63)`) and writes `x<S>/flats/<SSSS>/<SSSS>_<FF>.png` (8S×8S, colour type 3,
raw indices, full PLTE, `tEXt Exult-Src-CRC32` + `Exult-Origin`, zlib 9, deterministic) or `x<S>/flats.bundle`
(§5.7 layout, guard flag set), and `pack.txt` with `palette_crc32`. Marker: NN_S with `M` at (0,0) of every S×S
block (`M < 0xE0`, so P4 cannot reject it). Python 3.8 standard library only, so `make check-game` needs no venv;
1 s for 11,655 PNGs. On BG: 3,885 flats, palette CRC `c9c2c0e7` (the engine's R1 value), no flat with index 0xFF,
and every guard equals the guard of the same tile in `packs/bg` (3,885/3,885, cross-check with the art track).

## 6. Deviations from the spec (the code is the truth)

1. **`mkpack_identity.py` reads `shapes.vga`/`palettes.flx` itself**: `--dump-art` (WP-11) does not exist yet, so
   the templates are made in Python, and `palette_crc32` is **computed** (CRC32 of the clamped palette) instead of
   copied from `ref.txt`; the engine's R1 check and the coverage check catch a mismatch. It reads the static
   directory only (no `<PATCH>`); the oracles run with an empty patch. `--terrain` (WP-17) is not implemented.
2. **`overrides` defaults to `no`** in `--render-test` (§4.2 gives no default), so the NN oracles do not depend on the
   config or on the pack the sandbox links.
3. **Coverage check** for `expect=identity|marker` (not in §6.4): every flat cell of the view must be overridden.
   The marker prediction uses "the cell's flat source has an override" (from `Hires::flat`), which equals §6.4's
   "has a flat source" under full coverage.
4. **Toggle** is on → off → on (§6.4: on then off), so the generation check is tested in both directions; a key
   `toggle=1` rather than two runs.
5. **Repaints with a marker** must leave the render byte-identical (there is no NN reference); O7 is recorded but not
   compared for marker renders.
6. **`Chunk_terrain::get_flat_source`** (public) was split out of `paint_flats` so that the harness (and WP-10's
   inspector, `explain_at`) use the engine's own fill instead of a copy. `Paint_hires_flat` is a static function in
   `chunkter.cc` (no new file).
7. The generation is compared **only at S > 1** (§3.4 says "or `rendered_gen != Hires::generation()`"): at S = 1 a
   cache never holds overrides, and not calling into `Hires` keeps the S = 1 path as it was (I2).
8. **Per-terrain overrides** (`Hires::terrain`, precedence terrain → tile) are not wired: WP-17. The precedence today
   is tile → NN.
9. The **cold `render_flats` perf row** (deferred by WP-07) is in `perf.sh` as a gate (≤ 1 ms per cache) without a
   baseline line.
10. **Demo regions** "roads" and "dungeon" are not in `regions.txt` (which serves the oracles); the demo adds four
    regions of its own (§5).
11. **Side mismatch in `Paint_hires_flat`** (§3.4: "asserts in debug builds and falls back to NN in release"): no
    assert. The autotools builds (Linux, MSYS2) never define `NDEBUG`, so an assert would abort every non-MSVC
    build; the check returns false (NN for that cell) and logs one `[hires]` line per process, on every platform
    (I11: log, never crash). Unreachable today: `Store::flat` always returns `side = 8*scale` for its own scale.
