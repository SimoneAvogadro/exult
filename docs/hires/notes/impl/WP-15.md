## 2. Measurements and decision rules

All in `docs-hires/test/windows_matrix.md`. In short:
* **Matrix:** 5 renderers (`direct3d11`, `direct3d12`, `vulkan`, `opengl`, `software`) × 2 profiles (320x200 at
  1:1; the user's 3440x1440 fullscreen geometry: full 860x360, game 860x300, texture 5160x2160 at r = 0.667) ×
  {ARGB, INDEX8, both, PIXELART, real art} = 50 cases, run twice: **all pass**, every read-back exact.
* **Rule 1 (report):** 860 profile, S=6, scrolling p95 with real art: **D3D11 2.6-2.8 ms** (≤ 6.7 ms), D3D12
  7.5-7.7 ms. SDL's default renderer here is D3D11. Nothing to change; `max_world_mpx` stays 40.
* **Rule 2 (report):** Windows bundle 27-29 ms, loose 618-691 ms warm and 1.52 s on the very first read.
  WSL with `static` on drvfs: 1.4-1.6 s for either, caused by the source-flat fetch from `shapes.vga` over 9p
  (25.5 ms bundle / 122 ms loose with `static` on ext4). Recommendations: no preload; publish the bundle to `E:`.
* **Rule 3:** INDEX8 exact everywhere; `present_format=auto` resolves to INDEX8 on all five renderers.

## 3. Deviations from the spec (the code is the truth)

1. **§7.2 step 2: `WSLENV=MSYSTEM/u:CHERE_INVOKING/u` does not forward** on this system (Windows 10 19045):
   `cmd.exe /c echo %MSYSTEM%` sees nothing with `/u` and the value without a flag, so the first pacman runs
   ran under `MSYSTEM=MSYS` (harmless for pacman; the toolchain was then not on `PATH`). Use plain entries
   (`WSLENV=MSYSTEM:CHERE_INVOKING`, likewise `SDL_RENDER_DRIVER`), and strip a trailing `:` of an inherited
   `WSLENV` before appending. Proposed §12.6 item for §7.2 steps 2 and 7.
2. **§7.2 step 5: `-p`.** The run line needs `-p` (portable) to keep Exult's home out of
   `%LOCALAPPDATA%\Exult`, which is the 1.12.1 home (`exult.cfg`, `stdout.txt`, `stderr.txt`); `-c` alone moves
   only the config. The launcher sets the working directory to `ExultHires`, so `data` is found there.
3. **Interop runs need `data_path`.** A Windows process started from WSL gets a Linux `argv[0]`, so the
   exe-relative `data` fallback (`files/utils.cc`) misses; the scratch configs name `data_path`.
4. **Render-test keys** `walk=N` and `mode=plain` + `present=1` are new (§1.3). Rule 1's "walking with lerp on"
   is measured with the walk proxy, not an interactive session (the task forbids one; the desktop was locked).
5. **§7.2 step 7 "on both user profiles"**: the fullscreen profile was run as a 3440x1440 window with the same
   geometry (full 860x360, game 860x300), not fullscreen; read-back sizes matched.
6. **`perf_baseline.json`** gets no Windows line: `perf.sh` needs a Linux build tree and keys lines by
   `uname -n`, which is `SevenJars` on both sides. The Windows numbers live in `windows_matrix.md`.
7. **Bundle for rule 2:** `packs/bg` has no bundle (only `bg-r3-mixed-nn3` does), so `tmp/wp15/make_bundle.py`
   (u7hires from `hires-art`) wrote one into `tmp/wp15/packs/bg-bundle` and `E:\…\bench\bg-bundle`. The
   canonical packs and their `E:` mirrors are unchanged.
8. **Decision rules are reported, not applied** (task specifics, §13): no preload in `Shape_manager::load`,
   no `publish.sh` change.

**Decision needed from the user (§13, the measurement is not clean): decision rule 2.** Read literally, the
rule triggers twice: WSL bundle load 1.39-1.41 s (only with `static` on drvfs; the time is the source-flat

nothing on Windows) and to **publish `packs/bg` with its `flats.bundle` to `E:`** (27-29 ms) without loose
copies of bundled tiles (art track, `publish.sh` on `hires-art`). Neither is applied until the user decides.
