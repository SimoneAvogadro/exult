| Key | Values | Default |
|---|---|---|
| `render_scale` | `off`/`1`, `art`, `auto`, `force:N` | `off` (invalid → log, off) |
| `art_scale` | 1..8 | 6 |
| `max_world_mpx` | positive number | **40** (§13) |
| `present_format` | `auto`, `argb`, `index8` | `auto` (= INDEX8 when compiled and accepted) |
| `present_filter` | `auto`, `nearest`, `linear`, `pixelart` | `auto` (a forced filter is one direct pass, no halving) |

`--render-scale` overrides `render_scale` for the session (never written to the config). `EXULT_HIRES_FULL_UPLOAD=1`
uploads the whole world every frame. `aspect_y` (Auto only) is 1.2 for `Aspect Correct Fit` and the odd
`Centre` modes.

### 1.2 Present semantics (`show_world_scaled`)

* Resets first: device lost → skip drawing until `Game_window` rebuilds the surfaces; device reset →
  `free_layer_textures()`, `recreate_textures()`, full upload pending; targets reset → full upload pending.
* Upload: only when not in scene mode, and when the current target is the main buffer or a full upload is
  pending (a texture recreated while a layer was pushed is refilled from `draw_surface`, which still holds
  the last world). The rect is `world_writes.take()` through `tracked_to_phys`; ARGB palette changes
  convert everything (inside `upload`).
* Frame: `clear_window()` (window target, black), the world unless in scene mode, `composite_layers()`,
  `SDL_RenderPresent`. The screenshot path is the same without the present.

## 2. Deviations from the spec (the code is the truth)

1. **Tracked uploads already in WP-05.** §9 says WP-05 uploads the whole buffer and WP-14 adds the tracker;
   §3.2.4 describes the tracker. The tracker exists since WP-04 and `tracked_to_phys` is in this WP, so the
   upload is tracker-driven now (`EXULT_HIRES_FULL_UPLOAD=1` restores full uploads). In-game read-backs
   (§4.2) found no stale region.
2. **INDEX8 implemented now** (§9 puts it in WP-14; the task allowed it if cheap). It is the default
   (`present_format=auto`) on SDL ≥ 3.4 when the renderer lists INDEX8: the software renderer and WSLg's
   `vulkan` renderer do, and their read-backs are exact. WP-14 still owns the BG-region INDEX8 == ARGB oracle.
3. **No debug assert in `upload` for a clamped rect.** §3.2.4 asks for one, but §6.3 also requires a test
   that uploads a rect partly outside the texture; an assert would abort that test in every build without
   NDEBUG. `Stats::clamped` reports it instead and the test checks it. The engine never needs the clamp
   (`tracked_to_phys` already clamps).
4. **Screenshot hook in `UpdateRect`, not in `screenshot()`.** `UpdateRect` gets the one-line hook
   `if (world_scale > 1) return present_world_frame(for_screenshot);`, so `screenshot()` is untouched; the
   only S>1 caller of `UpdateRect` is the non-paletted screenshot.
5. **`present_world_frame` clears through `presenter.clear_window()`** so that the data-free test exercises the
   same clear (letterbox case).
6. **`World_presenter::create(renderer, draw8, pw, ph, format)`** takes the draw surface (INDEX8 needs its
   palette); `upload` takes a non-const surface (SDL's palette getter is non-const). `create` does not assert
   "the current renderer" (it simply binds to the renderer it is given; `free_surface` destroys the presenter
   before the renderer).
7. **`BuildGameMap` forces S=1 through the session override** (`set_render_scale_override("off")`), not
   `config->set(...)`, so a later `write_back` cannot persist it. (§3.3 lists this under WP-06; done here because
   the user's configs set `art` and the buildmap must stay 1x.)
8. **Device lost → rebuild (revised by the review fix, §9):** `Image_window` remembers the last
   `create_surface` size; `show_world_scaled()` itself calls `rebuild_surfaces()` (`free_surface()` +
   `create_surface()` with that size), because modal gumps, menus and the intro call `show()` without
   returning to the main loop. `rebuild_surfaces()` keeps the paletted picture and the palette (system memory
   outlives the renderer), so a loop that does not repaint shows the same frame again; it sets `world_rebuilt`,
   and the main loop's one-line hook `Game_window::rebuild_window_if_requested()` (before `rotatecolours()`)
   takes that flag and repaints. If S>1 cannot be set up again, the I11 latch gives S=1 and `show()` reruns on
   the upstream path. The window toast and `request_window_rebuild()` naming of §3.3 are not used (the toast
   is WP-06).
9. **`hires_config_changed()` has no caller yet**: VideoOptions has no render_scale entry (§1.3) and
   `--render-scale` is applied before the first window exists. WP-10's dev reload is the first caller.
10. **`ShouldPaintIntoGuardband`/`FillGuardband` hooks**: the first is a 3-line brace block (style), the second
    extends the existing `if (scene_mode)` condition.
11. **`[hires] present filter …` log line** on every filter change (not in the spec; it makes the ladder
    visible in user logs and was used for the smoke runs).
12. `exult --version` prints a compile-time capability line (§3.2.7); the runtime INDEX8 decision is logged
    at surface creation.

## 3. Tests

### 3.1 `test_world_scale` (`hires_unit`, 9 cases)

Parsers (all values, case/blanks, 10 rejects); every row of the §3.2.2 table at the table's 10 Mpx budget
(including the filter for each geometry: 1:1 NEAREST, 0.667×0.8 LINEAR, 573x200 PIXELART/LINEAR, 0.333 →
1 halving, 1720x600 → S=3, studio 1920x1200 → S=2, 3440x1440 Fill → S=1); the 40 Mpx default (860x300 and
1720x600 → 6, 1920x1200 → 3, 3440x1440 → 2); texture-limit edges (16380 vs 16386, a renderer limit, either
axis), inclusive budget edges for 6/3/2/1, off and empty areas, another S_art; `force:N` 2..8 ignoring the
budget and stepping by 1 under the texture limit; Auto (snapping up to a divisor, beyond S_art, aspect 1.2,
caps stepping down through divisors); a 20,000-input fuzz: art/auto give only 1/2/3/6, respect both caps, and
art is the largest fitting divisor; the ladder (equal integer ratios, mixed axes, ACF 1.2, HiDPI 1.25, exact
0.5, just below 0.5, 0.25 → 1 halving, 1/8 → 3, the k ≤ 6 bound, empty L/texture → skip, forced filters,
PIXELART without shader → LINEAR, 5,000-input fuzz: NEAREST never for a downscale); `tracked_to_phys`
(full 355x200 / game 320x200 / offset 17 at S=6, negative rects, partly and fully outside, empty, a
20,000-input fuzz against a logical-intersection model) and `clamp_phys`.

### 3.2 `hires_present` (§6.3, 10 new cases, each for ARGB and, with SDL ≥ 3.4, INDEX8)

| Case | Asserts |
|---|---|
| 1:1 | S ∈ {2, 6}: read-back == LUT(NN(indices)) exactly (random guard band bytes never show), bytes uploaded, filter NEAREST, L, no resolve/halving target |
| palette change | no writes and no change → 0 bytes; a palette tick → ARGB converts the whole texture, INDEX8 uploads 0 bytes; read-back == new LUT |
| partial / clamped | only the uploaded rect changes on screen; a rect partly outside is clamped (`clamped`, bytes = 7×7), a rect outside uploads nothing (ASan watches the locks) |
| r = 0.5 | read-back within ±1 of the 2x2 box of the LUT image (physical detail per pixel); resolve target only for INDEX8 |
| r = 0.25 | halving chain (1 target): within ±1 of the cascaded truncating 2x2 boxes (measured max error 0); direct LINEAR as negative control: max error 117 (> 32 required) |
| palette alpha 0 | r = 0.667 and r = 0.25: alpha-0 palette == alpha-255 palette, and not black |
| letterbox | 50x25 logical in a 100x100 window over a red backbuffer: bars black, middle == NN2 of the LUT image |
| resize after create | window 160x100 → 80x50 (LINEAR, matches the box) → 40x25 (halving) → 160x100 (NEAREST, exact) without recreating anything |
| resets | `SDL_PushEvent` of TARGETS_RESET / DEVICE_RESET / DEVICE_LOST reach the watch; flags are taken once; another window's id is ignored; full upload after targets reset and `recreate_textures()` after device reset give identical read-backs |
| destroy | after `destroy()` an event sets nothing; after the presenter is freed an event is harmless (ASan); an empty presenter draws/uploads nothing |

**Mutation check** (`tmp/wp05/mutate.sh`, `mutate2.sh`, build-o2): BLEND textures + palette alpha in the LUT,
no clear, no halving, no palette compare, no clamp (segfault), NEAREST instead of LINEAR, no targets-reset flag:
each is caught by at least one case. The LUT alpha alone survives, as intended: with blend NONE everywhere it is
neutral; the dangerous combination (blend BLEND with palette alpha) is caught by the alpha-0 case.

## 5. ASan game runs and two upstream problems found

The ASan exult cannot run a new BG game today, for reasons unrelated to the render path:

1. **Upstream UB, fatal under the lane's UBSan:** `schedule.cc:2701`, `Sit_actor_action(…) :
   Frames_actor_action(init(o, actor), 2)` calls the member `init()` (which writes the member `frames`) before
   the base is constructed: `runtime error: member call on address … which does not point to an object of type
   'Sit_actor_action'` during `Game_window::read_npcs()` → `restore_schedule()`. Reproduced at S=6 and at S=1
   (`--render-scale off`), 4 of 4 runs. UBSan suppressions do not apply because the lane builds with
   `-fno-sanitize-recover=undefined`. A fix (e.g. a static `init` filling a local array, since
   `Frames_actor_action` copies the frames) belongs on `upstream-fixes`; it was **not** made here.
2. **Harness hygiene:** after a run aborted during init, the next run finds the partly created gamedat, is no
   longer a "new game" (`fix_first` false), reads the original `npc.dat` as an Exult save and gets NPC 1's shape
   as 8820 → ASan SEGV in `Vga_file::get_shape` (`vgafile.h:374`). Deterministic (3/3) but caused only by the
   stale gamedat; with a fresh gamedat per run it does not occur. Game scripts must always start from an empty
   gamedat (`tests/game/lib.sh` already creates a fresh sandbox per run).

For the WP-05 ASan smoke, `schedule.cc` was patched **temporarily** (static `init`, restored byte-identical
from `tmp/wp05/schedule.cc.orig`): the ASan exult then ran the S cycle above (S=6→1→6→3→2→6→1→6, 90 s), the
BG intro in scene mode (75 s) and a WSLg session at `--render-scale force:6` (45 s) with **no ASan or UBSan
report**, and every saved frame NN-exact.

## 8. Known limitations

* Device reset and device loss are tested only through pushed events (the flags and the recreate path, and the
  `LD_PRELOAD` shim of §9); a real D3D11/D3D12 reset needs the Windows checklist (WP-15).
* ASan game runs of a new BG game stop at the upstream UB in `schedule.cc:2701` (§5); the fix belongs on
  `upstream-fixes` and is not part of WP-05.
* After a window resize SDL 3.2's software renderer picks up the larger surface only at the next present
  (seen in the 3.2 lane; the test presents once after resizing). In the engine that is at most one frame.
* The temporary instrumentation (frame dumps, the S cycle, the forced failure, the NPC print and the UB patch)
  is not part of the change; `grep -r WP05` over the tree is empty.

## 9. Review fix and finalization

**Fix step (after the independent review, `tmp/fix-wp05/`).** The lost-device rebuild moved from the main loop
into `show_world_scaled()` (deviation 8): a device lost while a modal gump, a menu or the intro was showing was
not rebuilt until the main loop ran again. `rebuild_surfaces()` now also restores the paletted picture and the
palette. Checked with an `LD_PRELOAD` shim (`tmp/fix-wp05/lostshim.c`) that pushes
`SDL_EVENT_RENDER_DEVICE_LOST` after a delay and hashes the read-back of the frames around it: in the menu
(build-o2, INDEX8) and in gameplay (build-sdl32, ARGB) the log shows `[hires] rebuilding the window surfaces`,
S=6 is set up again, the first present after the rebuild is the black clear of `create_scale_surfaces`, and
the next presents equal the last frame before the loss (menu) or continue the game. After the fix all four lanes
passed `make check` again (`tmp/fix-wp05/{linux,o2,asan,sdl32}_check.log`).

**Finalizer checks (2026-10-06, before committing):** `git diff --check` clean; no `WP05` marker in the tree;
`check_build_lists.py --strict`: 0 not allowed, 0 missing companions (2 pairs); clang-format 19.1.7: the four new
files are formatted, `clang-format-diff` over the changed lines of existing files is empty; build-o2 `make -j6`
had nothing to rebuild (the binaries match the committed sources) and `make check` PASS (`hires_unit`,
`hires_present`). No generated autotools file, build output, scratch file or EA-derived data is committed.

**ASan game smoke.** The fix step's ASan gameplay run (`tmp/fix-wp05/run-asangame`) ended in the ASan SEGV in
