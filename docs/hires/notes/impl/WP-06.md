## 2. Deviations from the spec (the code is the truth)

1. **No `Hires::generation()` check in `get_rendered_flats`.** §3.4 re-renders on a scale mismatch **or** a
   store generation change. The store and its glue (WP-08) live on branch `hires-store` and are not merged
   into `hires` yet, so `Hires::generation()` does not exist here. The cache checks the scale only; WP-09
   (per-tile composition, which merges the store and calls `Hires::flat` in `paint_flats`) adds the
   generation member and check next to `rendered_scale`.
2. **The clip skip applies at S>1 only.** §3.3 says "chunks whose 128x128 game-px rect misses the clip are
   skipped before the cache is touched" without a scale condition. At S=1 the skip would change when the
   flats of the margin chunks are rendered, and with it the order in which their shape frames are loaded
   (heap order, which decides ambiguous overlaps in the buildmap, WP-00 finding 2). Its benefit at S=1 is nil
   (a 16 KB render), so S=1 keeps upstream's call sequence exactly (I2). At S>1 the skip saves rendering an
   S² larger cache for the off-clip margin chunks (`paint_map` covers one extra chunk on each side).
3. **`blit` at every scale.** As §3.3 says; at S=1 `blit` of a 128x128 owned, offset-0 buffer is the same
   clip + row copy as the old `copy8` (the buildmap goldens below are unchanged).
4. **`Image_buffer8(128, 128, scale)` also at S=1.** It value-initialises; `paint_flats` starts with
   `fill8(0)` (P3) anyway, so the bytes are the same.
5. **Not done here (later packages, §3.3 rows):** `Game_render::test_passes` and `get_main_render_target()`
   belong to the `--render-test` harness (WP-07); `request_window_rebuild()` was replaced in WP-05 by
   `rebuild_surfaces()`; the `.reload` poll is WP-10.

### 3.1 Demo: BG at S=6 windowed under WSLg

`tmp/wp06/run` (build-o2), `render_scale=art`, window 1920x1200, game 320x200, 30 s under `timeout -k 5 32`
(exit 137 is the `-k` kill: SIGTERM only opens the quit gump, upstream behaviour). Log:
`[hires] render_scale art: world scale S=6 (full 320x200, output 1920x1200 …)`, `world texture 1920x1200 INDEX8
on renderer 'vulkan'`, `present filter nearest`. No error, no crash, no `mixed-scale` log line (every flats cache
is blitted at its target's scale). Run twice (before the temporary instrumentation and with the final binary).

Screenshots: an `LD_PRELOAD` shim (`tmp/wp06/keyshim.c`) pushes Ctrl-Alt-S (the engine's screenshot key) and
Alt-2 (perf overlay) at fixed times; the PNGs are kept in `tmp/wp06/demo/` (local only, EA-derived). The key
takes the RGB read-back path (`screenshot(dst, false)` → `present_world_frame`), 1912x1192 because upstream
crops the read-back by `guard_band` (4 px) on each side (also at S=1). Check (`numpy`): after the 2 px phase
shift of that crop, **every 6x6 block on the game-pixel grid is uniform** except the 39 blocks of the mouse
cursor (a UI layer), i.e. the world is NN ×6. Visual check of the Trinsic gameplay frame: correct. With the perf
overlay (mode 2) the new scopes show up: `paint_map flats: 225 us`, `paint_map flat RLE: 16 us`,
`paint_map objects: 573 us` (-O2, WSLg, one frame; WP-07 owns the measured perf baseline).

## 6. Review fixes (2026-10-06)

The independent review found three minor issues (DESIGN.md §12.3 W6-1..W6-4, revision 2.3).

1. **W6-1, the cache never shrank (fixed).** New private `Chunk_terrain::trim_render_queue()`
   (`objs/chunkter.{h,cc}`): while `queue_size > Figure_queue_size()` it frees and unlinks the least recently
   used terrain, stopping before `this`. `render_flats` calls it on the replace-in-place path (before the new
   allocation) and, in the new-cache path, after upstream's single eviction **only when `scale > 1`**. A pure
   S=1 session never takes the replace path, so its call sequence (and heap order) is upstream's (I2).
2. **W6-2, spec text (fixed).** DESIGN.md §3.3 now says the clip skip is S>1 only and why; §3.4 records the
   deferred generation check (W6-4) and the trim (W6-1).
3. **W6-3, no in-tree test (moved to WP-07).** `Chunk_terrain` needs `Game_window` and the shape files, so it
   does not link into the SDL-free `hires_unit`. DESIGN.md §6 (S-cycle row) and §9 (WP-07) now require the
   mixed-scale log check and a terrain-edit step at S>1.
